# PRISM — Pull Request Intelligence & Review Mesh

> **AI code review that understands your repository.**
> Deterministic analysis first, specialized AI agents second, an adversarial
> critic third — every finding ships with an evidence chain.

PRISM is a self-hostable, GitHub-native code review system. When a pull request
opens or changes, it ingests the diff **and the repository context around it**
(callers, services, database access, tests, conventions), runs deterministic
static analyzers, dispatches specialized review agents, challenges every
HIGH/CRITICAL result with an adversarial critic, and publishes an explainable,
evidence-backed review — inline comments, a summary, Markdown and JSON
artifacts, and a single risk score.

It is built around one principle: **a diff is not the whole story.**

---

## What makes PRISM different

- **Deterministic first.** A rules engine, secret scanner and dependency
  advisory checker run before any model is called. Findings are labeled
  `DETERMINISTIC`, `AI-DETECTED`, or `HYBRID`, and PRISM works fully offline
  with zero AI keys (rule-based mode).
- **Evidence chain for every finding.** Changed code → related code →
  repository context → deterministic evidence → AI analysis → critic
  verification → recommendation. No "the AI said so" black boxes.
- **Adversarial critic.** Every HIGH/CRITICAL finding is independently
  challenged ("Could this be wrong? What would disprove it?") and given a
  verdict of `CONFIRMED`, `WEAK`, `FALSE POSITIVE`, or `UNCERTAIN`.
- **Explainable risk engine.** Scores aggregate severity, critic confidence,
  security/correctness/performance/testing/dependency breakdowns, and change
  scope into `APPROVE`, `APPROVE WITH WARNINGS`, `REQUEST CHANGES`, or
  `BLOCK`, with the reasons shown.
- **Re-review with regression tracking.** Push a fix and PRISM diffs the new
  review against the previous one by finding fingerprint: **fixed, persistent,
  or new**, with the risk delta.
- **Grounded Copilot.** Ask questions about a review and answers cite the
  actual findings, files and evidence — never a private chain-of-thought. Only
  inputs, outputs, tools used, evidence, and status are exposed.
- **Honest by construction.** PRISM never executes pull request code, never
  fakes a connected integration (unconfigured providers are clearly labeled
  **DEMO MODE**), validates all model output as structured JSON, and redacts
  secrets from logs.

## Pipeline

```
GitHub App webhook (opened / synchronize / reopened)
        │  HMAC signature verified, idempotent by (repo, SHA)
        ▼
Ingestion ── PR metadata + base/head trees, blobs cached & SHA-keyed
        ▼
Context engine ── code graph: changed function → callers → services
        │                 → database → tests; language/framework detection;
        │                 architecture hints; repository memory & policies
        ▼
Deterministic analysis ── secret scanner · rules engine · dependency
        │                  advisories · external tools (semgrep/eslint/tsc
        │                  when present, auto-detected and skipped when not)
        ▼
Specialized review agents (parallel) ── security · bugs · performance ·
        │      tests (+ test generation) · maintainability · api-contract ·
        │      dependencies · intent agent   (structured/validated JSON)
        ▼
Adversarial critic ── challenges HIGH/CRITICAL; CONFIRMED / WEAK /
        │              FALSE POSITIVE / UNCERTAIN; suppresses nitpicks,
        │              duplicates, low-confidence and vague results
        ▼
Evidence verification ── every claim is bound to file/line + deterministic
        │                signal or safe-pattern convention
        ▼
Risk engine ── weighted score + breakdown + recommendation
        ▼
Synthesis ── inline comments, summary review, Markdown + JSON artifacts,
        │           token/cost accounting, correlation-id logging
        ▼
GitHub ── commit-pinned review published to the pull request (DEMO-labeled
          against fixture repositories)
```

The same pipeline is reachable through the dashboard, a manual trigger API, or
the durable job queue with retries, exponential backoff, idempotency keys and a
dead-letter queue.

## Quick start — DEMO MODE (zero configuration)

You need Node.js 20+ and npm. With no environment variables set, PRISM runs the
**full, real pipeline** against a bundled fixture repository. Demo data is
always labeled and is never mixed with connected repositories.

```bash
npm install
npm run dev
# open http://localhost:3000 → "Continue with demo environment"
```

Or bootstrap the demo via API:

```bash
curl -X POST http://localhost:3000/api/demo/bootstrap     # vulnerable PR (63/REQUEST CHANGES)
curl -X POST http://localhost:3000/api/demo/fix           # simulate author fix push (3/APPROVE)
```

### Scripts

| Command | Purpose |
|---|---|
| `npm run dev` | Next.js dev server (in-process worker starts automatically) |
| `npm run build` / `npm start` | Production build / serve |

## Going live

### 1. Create a GitHub App

1. GitHub → Settings → Developer settings → **GitHub Apps** → New GitHub App.
2. Set the **Webhook URL** to `https://<your-domain>/api/webhooks/github` and
   generate a **Webhook secret**.
3. Permissions: **Pull requests** (read/write), **Contents** (read-only),
   **Metadata** (read-only), **Issues** (optional, for comment reactions),
   **Checks** (optional).
4. Subscribe to events: `pull_request`, `push` (optional).
5. Note the **App ID**, download the **private key PEM**, and (for dashboard
   login) create an **OAuth client ID/secret**.
6. Install the App on your organization/account.

### 2. Configure the environment

Copy `.env.example` to `.env` and fill in:

```bash
PRISM_MODE=live
PRISM_BASE_URL=https://prism.your-domain.com
PRISM_SESSION_SECRET=$(openssl rand -hex 32)

GITHUB_APP_ID=123456
GITHUB_APP_PRIVATE_KEY_PATH=/run/secrets/prism-github.pem   # or GITHUB_APP_PRIVATE_KEY (one-line \n-escaped PEM)
GITHUB_WEBHOOK_SECRET=...
GITHUB_OAUTH_CLIENT_ID=...
GITHUB_OAUTH_CLIENT_SECRET=...

# Any one (or more) AI provider; with none set, PRISM stays deterministic-only
OPENAI_API_KEY=...                 # any OpenAI-compatible endpoint (Together, Groq, OpenRouter, vLLM, Ollama…)
# GEMINI_API_KEY=...
# ANTHROPIC_API_KEY=...
PRISM_AI_PROVIDER=auto             # auto | openai | gemini | anthropic | local
```

Every variable is optional: missing credentials degrade to the local
deterministic analyzer and clearly-labeled DEMO MODE rather than pretending an
integration is connected.

### 3. Review modes & policy

Modes (`PRISM_REVIEW_MODE`, or per-PR): `fast` · `standard` (default) ·
`deep` · `security` · `test`. In the dashboard, **Policies** map
severity to publication behavior (e.g. CRITICAL → REQUEST CHANGES), enforce
"AI findings are merge-blocking only when deterministic corroboration exists",
require test coverage for changed behavior, and manage **path reviewers** and
repository memory. Token ceilings (`PRISM_MAX_AI_TOKENS`) and cost budgets
(`PRISM_AI_COST_BUDGET_USD`) are hard limits, and token/cost usage is tracked
per review.

## Security model

- **PRISM never executes pull request code.** It parses and statically
  analyzes source text only; there is no sandbox-escape surface because no
  user code is ever run.
- **Webhooks** are HMAC-signature verified and idempotent; reviews are pinned
  to full commit SHAs and snapshots are immutable/content-addressed.
- **Secrets** come from environment variables (or mounted key files), never
  from the repository; tokens and sensitive values are redacted in logs.
- **AI output is untrusted by default:** responses must validate against Zod
  schemas or are discarded; only deterministic corroboration can make an AI
  finding merge-blocking when policy requires it; prompt/tool inputs are
  bounded by token and cost budgets.
- **Tenant isolation:** all data access is scoped through installation →
  organization → repository authorization checks; demo data is hard-partitioned
  from connected repositories.
- **Sessions** are signed httpOnly cookies (`PRISM_SESSION_SECRET`).
- **Observability without leaking reasoning:** logs and the agent run traces
  show decision summaries, inputs, outputs, tools, evidence and status —
  never private chain-of-thought.

See [**SECURITY.md**](./SECURITY.md) for the full policy and vulnerability
reporting process.

### Reliability

Durable jobs (SQLite-backed `jobs` table with row-locking claims, or a Redis/
BullMQ adapter point) provide retries with exponential backoff and jitter,
dedupe keys (e.g. `review:<pr>:<sha>:<mode>`), stale-job recovery, and a
dead-letter queue. Blob/snapshot reads are SHA-keyed caches; all state
transitions are safe to replay.

## Deployment notes

- The reference deployment uses SQLite (`PRISM_DATABASE_PATH`) — perfect for a
  single-node setup. The data-access layer is the only database boundary;
  point it at Postgres (`DATABASE_URL`) for horizontal scale.
- Run one or more `npm run worker` processes separately from the web tier in
  multi-replica setups; the jobs table's claim lock (or Redis) coordinates them.
- Put the service behind HTTPS (required for GitHub webhooks and OAuth).
- Static external tools (`semgrep`, `eslint`, `tsc`) are optional: they are
  detected at runtime, used when present, and reported honestly when absent.

### Current limitations / roadmap

- Hosted SaaS, Slack/Teams notifications, and MR support for GitLab/Bitbucket
  are not implemented; the ingestion boundary is the designed extension point.
- Language intelligence is deepest for TypeScript/JavaScript today; the parser
  and rules engine are the generalization points for additional languages.
- AI models can be wrong: that is why deterministic corroboration, the critic,
  evidence binding and human review are part of the design — PRISM recommends,
  humans merge.
